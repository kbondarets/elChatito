# elChatito

Локальный чат для моделей apimira ([OI]-совместимый API). Работает на вашем компьютере,
ключ хранится только у вас и в браузер не попадает.

## Что уже умеет (версия 1)

- Создавать несколько чатов и переключаться между ними.
- **Сразу открывать чат при запуске**: приложение само открывает последний чат,
  а если чатов ещё нет — создаёт новый. Нажимать «+ Новый чат» нужно только тогда,
  когда хочется начать новую переписку.
- Переименовывать чаты (кнопка ✎) и удалять их (кнопка ×, с подтверждением).
- Выбирать модель из выпадающего списка (все модели каталога с пометкой типа).
- Отправлять сообщение и получать ответ модели.
- **Прикреплять файлы и фото**: кнопкой со скрепкой, перетаскиванием в поле ввода
  или вставкой из буфера (Ctrl+V). Картинки модель «видит», из документов
  извлекается текст — см. раздел «Файлы и фото».
- **Рисовать и менять картинки**: у моделей типа «картинки» поле ввода становится
  генератором (нарисовать по описанию) и редактором (изменить готовую картинку) —
  см. раздел «Картинки: рисовать и менять».
- Смотреть ответ «вживую»: текст печатается по мере генерации, с мигающим курсором.
- Продолжать диалог в том же чате (модель помнит контекст чата).
- Сохранять чаты на диск — они не пропадают при перезапуске.
- Узнавать приложение по эмблеме: морда кота в углу и иконка во вкладке браузера.

## Быстрый запуск

1. Впишите свой ключ в файл `.env` (строка `apimira_api_key=...`).
2. Дважды щёлкните `start.bat`.

Через несколько секунд откроется браузер на `http://127.0.0.1:5173`.
Чтобы остановить — закройте чёрное окно терминала.

## Запуск вручную

```powershell
npm install     # только при первом запуске
npm run dev     # бэкенд на 3000 + интерфейс на 5173
```

Затем откройте `http://127.0.0.1:5173`.

## Список моделей

Список не фиксирован — сервер сам тянет его из apimira при запуске:

- `GET /v1/models` — какие модели доступны;
- `GET /v1/account/pricing` — название, тип и возможности каждой модели.

В выпадающем списке — все модели каталога с пометкой типа: «GPT-6 Astra · чат»,
«Veo 3.1 · видео», «GPT Image 2 · картинки». Модели с возможностью видеть картинки
помечены глазом 👁, умеющие править картинки — кистью 🖌. Модели типов «картинки»
и «видео» в текстовом чате не работают (шлюз вернёт ошибку): «картинки» открывают
генератор/редактор, а «видео» пока показаны для полноты картины.

Чтобы обновить список — просто перезапустите приложение.

Посмотреть список вручную:

```powershell
node scripts/list-models.js
```

## Если apimira не открывается без VPN

В некоторых сетях провайдер «глушит» обычный DNS: запросы на 53-й порт не
получают ответа, и `apimira.com` перестаёт находиться — хотя сам сервер при
этом доступен напрямую. Тогда кажется, что приложение работает только через VPN.

elChatito умеет обходить это сам. Если обычный DNS не ответил, приложение
спрашивает адрес у DNS-over-HTTPS (DoH) — это обычный HTTPS на 443-м порту,
который почти никогда не блокируют. VPN для этого не нужен.

Как это устроено и как настроить:

- Работает автоматически, ничего включать не надо. Если обычный DNS в порядке —
  поведение вообще не меняется.
- Сервер DoH по умолчанию — Cloudflare (`https://1.1.1.1/dns-query`). В адресе
  указан IP, а не имя, иначе мы бы упёрлись в тот же сломанный DNS.
- Изменить или выключить можно в `.env`:

  ```ini
  doh_enabled=1                              # 0 — выключить запасной DNS
  doh_server=https://1.1.1.1/dns-query       # можно https://8.8.8.8/resolve
  ```

- Запасной путь надстраивается над системным резолвером, поэтому работает и для
  `fetch`, и для любых других сетевых запросов этого процесса. Ответы кэшируются
  на 5 минут.

Проверить, что дело именно в DNS: `node scripts/list-models.js` — если список
моделей приходит, apimira доступна.

## Файлы и фото

Прикрепить файл можно тремя способами: кнопкой со скрепкой, перетаскиванием файла
прямо в поле ввода (появится подсвеченная зона) или вставкой из буфера — Ctrl+V
(удобно для скриншотов). Как файлы попадают в модель:

| Файл | Что делает elChatito |
| --- | --- |
| Картинки (PNG, JPEG, WebP) | Отправляются как изображения — модель их «видит». Нужна модель с 👁. |
| Текст и код (TXT, MD, CSV, JSON, XML, YAML, JS, PY, …) | Содержимое уходит в модель как текст. |
| PDF | Из содержимого извлекается текст (best-effort). |
| DOCX | Из содержимого извлекается текст. |
| Прочее | Отклоняется с понятным сообщением. |

Ограничения: до 5 МБ на картинку и до 20 МБ на документ; для PDF понимается только
текст из простых шрифтов (сложные и сканированные документы могут дать пусто).
Тип картинки определяется по содержимому файла, а не по имени: apimira принимает
только PNG, JPEG и WebP, поэтому GIF, BMP и AVIF отклоняются сразу (с понятной
подсказкой), а не «сюрпризом» в виде ошибки шлюза. Файлы хранятся локально в
`data/uploads/` и в браузер не уходят; на сервер отправляются только выбранные вами файлы.

## Картинки: рисовать и менять

Модели типа «картинки» (например, `openai/gpt-image-2`) работают не как чат, а как
генератор и редактор. Выберите такую модель в списке — поле ввода превратится в
промпт, а над ним появятся режимы:

- **Нарисовать** — создаёт картинку по описанию (`POST /v1/images/generations`).
  Укажите, сколько кадров нужно (1–4), — они появятся в переписке картинками.
- **Изменить** — правит уже готовую картинку по описанию
  (`POST /v1/images/edits`): заменить фон, дорисовать деталь, повторить стиль.
  Прикрепите картинку (скрепкой, перетаскиванием или Ctrl+V), напишите, что
  изменить, и выберите размер кадра. Режим доступен только у моделей с пометкой 🖌.
  Кнопка **🖌 Изменить** под любой картинкой в переписке сразу подставляет её в
  редактор — удобно дорабатывать результат по шагам.

Промпт — до 15 000 символов. Правка может занять несколько минут: подождите, не
закрывая вкладку. Если модель не умеет править картинки, кнопка режима неактивна.
Готовые кадры сохраняются в `data/uploads/` и открываются по клику в полном размере.

## Работа с git

Проект хранится на GitHub, ветки ведутся по простой схеме:

- **`main`** — всегда рабочая версия (то, что запускается). Напрямую в неё ничего не льём.
- **`feature/<имя>`** — новая возможность (например, `feature/system-prompt`).
- **`fix/<имя>`** — исправление ошибки.

Каждая доработка делается в отдельной ветке, созданной от `main`, с прогоном тестов;
в `main` ветка вливается только после проверки. Так новая фича не может сломать
стабильную версию.
